# 商城结算与优惠券模块 PRD（演示用）

版本：v1.2    作者：产品部    日期：2026-09-01

## 1. 概述

本需求描述 C 端商城「购物车结算」「优惠券使用」「订单提交」三个功能的交互与规则，适用于 App 与 H5。

## 2. 结算流程

### 2.1 购物车结算

- 用户在购物车点击「去结算」进入结算页。

- 结算页展示：商品明细（名称、单价、数量、小计）、合计金额、运费、优惠金额。

- 商品数量调整区间：1 至库存上限，库存实时校验，超过库存提示「库存不足」并回退数量。

- 取消勾选的商品不参与结算。

### 2.2 运费

- 满 99 元包邮，不满 99 元收取 8 元运费。

- 偏远地区（新疆、西藏、内蒙古）运费规则另行配置，本版不做线上实现。

### 2.3 提交订单

- 点击「提交订单」后先校验库存与优惠，再创建订单。

- 排队高峰时段提交可能失败，需重试（重试策略待定）。

- 提交成功后跳转收银台；返回的订单状态以服务端为准。

## 3. 优惠券

### 3.1 券类型

- 满减券：满 X 减 Y；折扣券：全场 Z 折。

- 优惠券不可叠加使用，一张订单最多使用一张。

- 优惠金额 = 商品小计合计 - 运费(若参与) ，抵扣规则细节待确认。

### 3.2 领券与过期

- 优惠券领取后有效期为 N 天（N 未定）。

- 过期/已使用/当前不可用（未达门槛）的券在结算页置灰，并给出不可用原因。

## 4. 异常与边界

- 库存不足、券已过期、金额计算异常（异常金额上限未定义）时的提示语与阻断逻辑需确认。

- 并发下单同一商品，库存扣减需保证不超卖。

## 5. 接口约定

- POST /api/cart/checkout、POST /api/coupon/apply、POST /api/order/submit。

- 统一响应：{ code, message, data }；列表接口默认每页 20 条（分页上限未定义）。

## 6. 性能要求

- 结算页首屏打开时间不超过 2 秒（P90）。

- 秒杀/大促期间 QPS 与降级策略未定义，需压测后再定。
